# dynamic-content-blocks

MVP двух новых блоков для редакторской сетки главной [The Bell](https://thebell.io): **витрина подписных продуктов с ежедневной ротацией** и **вебинары** с общим checkout в двух режимах — **Demo** и **Live**.

> **Два режима оплаты в одной кодовой базе.** **Demo** — наши модалки тариф → оплата → успех, mock-шлюз и тестовые карты: деньги не списываются, данные карты не сохраняются, права хранятся только в этом браузере. **Live** — после выбора тарифа читатель переходит на официальный checkout The Bell; приложение не запрашивает карту, не показывает успех и не выдаёт права. Подробнее — раздел «Режимы checkout».

## Запуск

Требования: Node.js 24.x, не ниже 24.15.0 (минимальная версия 24-й ветки для Angular 22.3), и npm, входящий в его поставку.

```bash
npm ci
npm start            # http://localhost:4200
```

Полезные параметры демо:

- `?checkout=demo` / `?checkout=live` — переключить режим оплаты для этого открытия (см. «Режимы checkout»).
- `?demoNow=2026-11-22T23:59:50%2B03:00` — запустить часы приложения с указанного момента (время продолжает идти). Через минуту витрина переключится на следующий продукт без перезагрузки.
- Тестовые карты: `4242 4242 4242 4242` — успех, `4000 0000 0000 0002` — отказ банка, `4000 0000 0000 0119` — сбой платёжного сервиса. Принимаются только эти номера: любая другая карта отклоняется ещё в форме, а mock-шлюз дополнительно отклоняет неизвестный номер. Поля карты с масками: номер — 16 цифр группами по 4, срок — ММ/ГГ (месяц 01–12, не истёк), CVC — 3 цифры. Реальные данные карты вводить нельзя.
- Сброс покупок: `localStorage.removeItem('dcb.purchases.v1')` в консоли.

## Архитектура

Один Angular-монолит, четыре функциональных модуля, у каждого слои `bootstrap / core / data / ui` (гексагональный подход: core определяет порты, data их реализует, bootstrap связывает через DI).

```
src/app/
  app.config.ts      composition root: подключает провайдеры всех модулей
  shared/            Clock, KeyValueStorage, modal-shell, форматирование — без бизнес-логики
  modules/
    products/        каталог, тарифы, права (entitlements), ротация, витрина
    webinars/        вебинары, статус по времени, правило доступа, блок
    checkout/        сценарий покупки, mock-шлюз, хранилище покупок, модалки
    home/            редакторская конфигурация сетки, статьи, страница
```

| Слой        | Содержимое                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------- |
| `bootstrap` | `configuration/` (конфиги модуля) и `providers/` (`data`, `core`, `index`) — только DI-связывание |
| `core`      | `interfaces/`, `tokens/`, `facades/`, `rules/` (чистые функции), `models/`                        |
| `data`      | репозитории, источники данных, мапперы, адаптеры (localStorage, mock payment)                     |
| `ui`        | standalone-компоненты OnPush, работают только с фасадами                                          |

### Граф зависимостей (импорты)

```
home ──► products(ui, core), webinars(ui, core)
webinars ──► products(core)
checkout ──► products(core)
products ──► shared        (все модули ──► shared; shared ни от кого)
app (корень) ──► все модули  (checkout импортирует только корень: провайдеры — app.config.ts, модалка CheckoutHostComponent — app.ts)
```

Циклов нет, и это проверяется: `npm run arch` запрещает `products → {home, webinars, checkout}`, любой импорт `checkout` из других модулей (корень `src/app/app*.ts` под это правило не попадает), `core → data/ui/bootstrap`, `ui → data`, `shared → modules`.

### Как блоки запускают checkout без циклических импортов

- **Контракт** `SubscriptionCheckout` и токен `SUBSCRIPTION_CHECKOUT` лежат в `products/core` (products — коммерческий каталог: продукты, тарифы, права).
- **Инициаторы**: `ProductShowcaseFacade` (`{ kind: 'product' }`) и `WebinarsShowcaseFacade` (`{ kind: 'entitlement' }`).
- **Реализация**: `CheckoutFacade` в `checkout/core`.
- **Связывание**: `checkout/bootstrap/providers/core.providers.ts` — `{ provide: SUBSCRIPTION_CHECKOUT, useExisting: CheckoutFacade }`.
- **Права**: порт `ENTITLEMENT_QUERY` (тоже в `products/core`) реализует `EntitlementService` в checkout: права = объединение `grants` тарифов из сохранённых покупок по актуальному каталогу. Отдельные флаги доступа не хранятся.
- **Источник истины о покупках**: `LocalPurchaseRepository` (`checkout/data`), ключ `dcb.purchases.v1`.

## Редакторская конфигурация

`modules/home/bootstrap/configuration/home-grid.config.ts` — типизированный массив `GridItemConfig` (порядок = порядок на странице):

```ts
{ kind: 'article', id, span, articleId, emphasis: 'hero' | 'cover' | 'text' }
{ kind: 'product-showcase', id, span, settings: { mode: 'rotation' } | { mode: 'pinned', productId } }
{ kind: 'webinar-showcase', id, span, title, presentation: 'feature' | 'list',
  settings: { rule: 'upcoming-then-recent', limit, series? } | { rule: 'manual', webinarIds } }
```

`span` — ширина ячейки в 12-колоночной сетке: `full` = 12, `half` = 6, `third` = 4, `quarter` = 3 колонки. На планшете (768–1023px) половины и трети сохраняются, текстовые новости идут по две в ряд; на мобильном всё в одну колонку. `emphasis` задаёт вид статьи: широкая обложка, карточка с обложкой или текстовая строка. `presentation` у вебинаров: `feature` — одна крупная карточка с обложкой, датой, статусом и CTA; `list` — строка из нескольких компактных вебинаров.

Демонстрационная раскладка по образцу главной The Bell: 4 текстовые новости → статья 1/2 + вебинар The Bell.Tech 1/2 → две статьи 1/3 + продукт дня 1/3 → главная история на всю ширину → строка вебинаров The Chat (ближайший и прошедшие) → две статьи 1/3 + закреплённый Unlimited 1/3. Использованы только 10 проверенных статей; заголовок каждой — ссылка на саму статью на thebell.io (адреса проверены 23.11.2026: страница открывается, заголовок и дата совпадают), открывается в новой вкладке, у карточек с обложкой кликабельна вся площадь при одной остановке Tab. Тест `home-grid.config.spec.ts` проверяет валидность конфигурации и то, что в этой раскладке все ряды заполнены на десктопе и планшете; жёсткого запрета неполных рядов для редакции нет.

Витрина продукта — компактная карточка 1/3: продукт, подзаголовок, предложение и кнопка. Подробности и тарифы — в модалке checkout. Конфигурация не содержит состояния подписки читателя. Ошибочные записи (дубликат id, неизвестная статья, неизвестный закреплённый продукт, неизвестный вебинар) не ломают страницу.

## Ротация

`products/core/rules/select-showcase-product.ts`: `пул[(день − epochDay) mod N]`, где «день» — календарная дата в `Europe/Moscow`, а пул — порядок `news → tech → invest → unlimited` без продуктов, закреплённых на этой же странице; N — размер пула. Эпоха `2026-01-01` (`products/bootstrap/configuration/rotation.config.ts`). Детерминированно, без случайности; закреплённый продукт имеет приоритет; неизвестный закреплённый id → fallback на ротацию.

Продукт не повторяется на одной странице (`home/core/facades/home-grid.facade.ts`; правила вычисляются из конфигурации, редактору ничего дополнительно настраивать не нужно):

- закреплённые на странице продукты исключаются из ротации. В демо-раскладке закреплён Unlimited, поэтому продукт дня идёт по циклу из трёх: 23.11 Invest, 24.11 News, 25.11 Tech, 26.11 Invest и так далее. Если убрать закреплённый слот, Unlimited возвращается в ротацию и цикл снова из четырёх;
- второй слот, закреплённый на тот же продукт, не выводится;
- выводится только первый ротируемый слот (слот с неизвестным закреплённым id тоже ротируется и считается ротируемым);
- если все продукты ротации закреплены на странице, ротируемый слот не выводится: молча повторять продукт нельзя. Время берётся из порта `CLOCK`; фасад пересчитывает выбор раз в минуту, поэтому продукт меняется после полуночи без перезагрузки.

## Вебинары

- Статус (`upcoming`/`started`/`past`) вычисляется из текущего времени. Длительность эфира и время публикации записи не объявлены, поэтому время окончания не придумывается. До начала — «Скоро» и «Получить доступ». С момента начала — «Эфир начался»: эфир мог уже закончиться, поэтому доступ к нему больше не продаётся; читатель без права видит «Эфир уже начался, время окончания не объявлено. Подробности — на странице события», подписчик — «Участие входит в вашу подписку: ссылка на эфир — в письме The Bell». Полночь по Москве — только граница отображения: со следующего дня дата события прошла, и карточка показывает «Прошёл»; это не вычисленное время окончания эфира. Если известна только дата — вебинар «будущий» до конца этого дня в указанном часовом поясе. Неразбираемая дата → карточка скрыта.
- В Live приложение не видит настоящих подписок. Поэтому в окне тарифов для ещё не начавшегося Tech-вебинара показано: «Уже подписаны на The Bell.Tech или The Bell.Unlimited? Повторная покупка не нужна: ссылка на вебинар придёт на почту примерно за час до начала» (так написано на странице вебинара). В Demo этой строки нет: там видны демо-права.
- Доступ определяется правом, а не продуктом: Tech-вебинар требует `tech.webinars`, его дают платные тарифы Tech и все тарифы Unlimited; пробный Tech и тарифы Invest — нет: пробный тариф открывает вебинары и полный архив только со 2-го месяца, при переходе на полную стоимость, поэтому в демо он прав на вебинары не даёт и для вебинара не предлагается.
- Запись упоминается только там, где её анонсирует источник (Tech: «Запись анонсирована для подписчиков»). После эфира запись не продаётся и не обещается, пока редакция не подтвердит публикацию (`recording.published`); до этого — «Запись пока не опубликована». Для The Chat — «Запись не анонсирована».
- The Chat — членство с рекомендациями и модерацией; через наш checkout не продаётся, карточка ведёт на the-chat.io.

Параметр `?checkout=demo` или `?checkout=live` переопределяет его; другие значения игнорируются (`checkout/bootstrap/configuration/resolve-checkout-mode.ts`).

| ----------------------------------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------- |

## Checkout

Состояние — discriminated union `closed | tariffs | payment(idle|submitting|declined|error) | redirect | success`; `payment` и `success` бывают только в Demo, `redirect` — только в Live. Проверки в `checkout/core/rules/check-tariff-eligibility.ts`, независимо от UI:

- тариф существует (ID проверяется по списку, тип тарифа — явное поле `kind`, а не суффикс ID);
- `product`-запрос → тариф принадлежит продукту; `entitlement`-запрос → тариф даёт право (Unlimited подходит для Tech-вебинара);
- нельзя купить тот же тариф повторно; пробный — только без покупок этого продукта; смена платного тарифа — вне MVP.

Повторная отправка во время обработки игнорируется, модалку нельзя закрыть во время оплаты. Права появляются только после `approved`. Если хранилище недоступно, покупка остаётся в памяти, и UI прямо говорит, что она пропадёт после перезагрузки.

**Несколько вкладок (Demo).** Источник истины — localStorage, а не память вкладки. Покупки перечитываются при открытии checkout, при выборе тарифа, перед оплатой и ещё раз после ответа mock-шлюза; запись делается поверх только что прочитанного списка; другие вкладки обновляются по событию `storage`. Удалённые в другой вкладке покупки не восстанавливаются из памяти. Если после ответа шлюза покупка уже недопустима (тот же тариф или тариф этого продукта оформили в другой вкладке), она не сохраняется, экран успеха не показывается, читатель возвращается к тарифам с объяснением.

Ограничение: синхронизация не транзакционная — у localStorage нет блокировок и атомарного «прочитать и записать» между вкладками. Если нажать «Оплатить» в двух вкладках почти одновременно (в пределах ~1,2 с обработки mock-шлюза), шлюз ответит «успешно» в обеих. Покупки не потеряются, повторная или запрещённая покупка не сохранится и не получит экрана успеха, но двойное «списание» в демо не предотвращается. Web Locks API сознательно не используется: в Live локальных покупок нет, а в production от двойной оплаты защищает сервер.

`shared/ui/modal-shell` — только техника: нативный `<dialog>`, Esc, overlay, фокус, `aria-labelledby`, блокировка прокрутки. Шаги и бизнес-сценарий — в `checkout`.

## Путь в production

Выбранный вариант — **существующий checkout The Bell**; режим Live уже ведёт на него для всех 13 тарифов. Чего не хватает для полноценного production:

- возврат читателя после оплаты и подтверждение результата от backend The Bell;
- права из личного кабинета: новая реализация `PURCHASE_REPOSITORY` вместо `LivePurchaseRepository`, которая сейчас честно возвращает пустой список.

Наших модалок оплаты и успеха в Live нет — это осознанное изменение UX; сценарий модалок из ТЗ показывается в Demo.

## Ограничения

- Demo: mock-оплата, права только в localStorage этого браузера. Live: реальная оплата на thebell.io для всех 13 тарифов; после внешней оплаты прототип не получает серверного подтверждения и не активирует подписку — доступ здесь не появляется.
- Официальные checkout URL могут смениться: проверены 23.11.2026. Сумма пробного тарифа Tech на странице оплаты ($1,01) отличается от каталога ($1).
- Нет авторизации, серверного биллинга, продлений и смены тарифа.
- Вебинары The Chat — внешнее членство, ведут на the-chat.io в обоих режимах.
- Только USD: рублёвые цены опубликованы не для всех тарифов.
- Разовое участие в вебинаре Tech опубликовано на странице вебинара за $25 (с записью и слайдами) и оплачивается там же через Stripe (Payment Link на странице организатора). Это отдельная покупка на стороне организатора, не подписочный тариф: в MVP её нет, четырнадцатый тариф не добавлялся. Для вебинара предлагаются только подписочные тарифы, которые дают доступ, а «Страница события» ведёт на официальную страницу.
- После начала вебинара его карточка не ведёт в окно тарифов (см. «Вебинары»), а после даты события — тоже, пока публикация записи не подтверждена. Сценарий покупки из вебинара показывается на дату до эфира: `?checkout=demo&demoNow=2026-11-24T12:00:00%2B03:00`.
- Каталог продуктов, вебинаров и статей — локальные типизированные данные, проверенные 22.11.2026 по публичным страницам; они устареют.
- Обложки статей, вебинаров и продуктов сгенерированы CSS (цвет по рубрике или серии): фотографии The Bell не копировались, изображения не придумывались.
- Проверка «один основной экспорт на файл» — ручная (стабильного правила ESLint нет).
